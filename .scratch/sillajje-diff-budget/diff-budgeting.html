Diff size in the sillajje sub-generator

The full diff goes into every prompt, with no size cap. The fix is a per-file budget that keeps paths and drops content.

2026-10-04 scope: sillajje-core, sillajje-jj, sillajje adapter

Summary

Three code paths fetch a diff, and all three fetch the whole thing. None of them cap it. The diff is then interpolated into the prompt verbatim, and the subagent port carries no token or context limit either. So a big file does not degrade gracefully: it makes the prompt big, the provider call fails, the retry wrapper burns its attempts, and the stamp falls back to a weak subject or an empty trace.

The improvement you describe — keep the file name and the change stat, drop the content — is a per-file budget applied before prompt assembly. It belongs in sillajje-core as a pure function, fed by the existing diff string or by new per-file jj reads.

Why it bites

A diff that overflows the model's context does not produce a "file changed" line. It makes the call fail, and runWithRetry (sub-generator.ts:224) retries maxAttempts times — three by default — before the fallback fires. The user pays three failed calls and gets deriveSubject(prompt) for the header, an empty trace, or chore: manual checkpoint for a manual header.

Three more costs, in order of how often they matter:

  • Wasted signal. The trace templates say the narrative must be "grounded in the transcript, not in the file diff" (sub-generator.ts:135, :157, :179). For an interaction stamp the diff is auxiliary, so a full diff can spend most of the prompt on text the trace is told to ignore.
  • The diff is the only signal in three paths. A rev stamp, a manual session stamp, and a fold have no transcript. Their header and summary still come from the diff, so a hard budget must not blank the diff entirely there.
  • Memory, not just context. Fetching the whole diff materializes it as a JS string before any cap runs. A generated file or a lockfile with a million lines is a real memory event even if the prompt is later trimmed.

Note where the user's 200k figure sits. That is a prompt ceiling, not a diff budget. The diff should get a fraction of it, because the transcript, the header template, and the model's own output need room.

Improvement options

A. Condense the diff string

A pure function in sillajje-core: split the jj diff into per-file sections on the jj header lines (Modified regular file <path>:, Added …, Deleted …, Renamed …), keep small sections, and replace a large section with its header plus diff omitted (N lines). Enforce a global budget; once spent, list the rest path-only.

Hermetic and unit-testable against captured diff text. Does not stop the big string from being materialized first.

B. Fetch per-file from jj

Never build the big string. Read jj diff --stat -r <rev> for the file list with add/delete counts, then fetch each small file with jj diff -r <rev> <fileset> while the budget lasts. Emit omitted files as <status> <path> (+a/-b) — content omitted.

Bounded memory and a hard cap. Costs more jj invocations and needs new boundary methods, because Jj.diff does not take filesets today.

C. Ignore generated paths

A configurable skip list, like fold's --exclude: lockfiles, dist/**, *.min.js, snapshots. Omit them regardless of size. Cheapest win for the common big-file case.

D. Budget transcript too

A single assistant response can be as large as a diff. Cap the transcript with the same budget machinery, and for an interaction stamp drop diff content before dropping transcript, since the trace is transcript-grounded.

Option A is the smallest change and fits the existing tests. Option B is the correct long-term boundary and subsumes A's memory concern. C is orthogonal and should ship with either. D closes the second unbounded input.

Recommended shape

Add a condenseDiff module to sillajje-core with a pure, unit-tested core, and give it two config knobs under subGenerator:

subGenerator: {
  diff: {
    maxBytes: 200_000,      // whole condensed diff budget
    maxFileBytes: 20_000,   // per-file content budget
    omit: ["pnpm-lock.yaml", "*.lock", "*.min.js", "dist/**", "*.snap"],
  },
}

The condensed diff keeps the jj header line for every file, so the header generator can still infer a scope from the paths. Content survives only for files under maxFileBytes and only while maxBytes allows.

Then:

  • Call condenseDiff at each fetch site — interaction.ts:67, diff-only.ts:50, fold.ts:660 — so all three paths and the manual header path share one budget.
  • Keep the {{diff}} substitution unchanged. Condensing is an input transform, not a prompt change.
  • Emit one status when content was dropped, for example info code diff-condensed with the count of omitted files. Omitting silently would make a weak stamp look like a model failure.
  • Track budget in bytes or estimated tokens (chars / 4), never in lines alone: a line of minified JS is not a line of source.
  • Do the memory-safe version (option B) when convenient: expose diffStat and let Jj.diff accept filesets, so the big file is never read.

Open questions

  • Budget unit. Is the 200k a prompt ceiling you want enforced with a token estimate, or is the diff budget a separate smaller number? A token estimate is fuzzy without a tokenizer; bytes are exact and hermetic.
  • Where the cap lives. Option A is a pure function in the core and needs no boundary change. Option B is the right boundary but adds diffStat and a filesets option on Jj.diff. Which do you want first?
  • Granularity. Per-file, or per-hunk? Keeping the first hunk of every large file preserves a hint of what changed; it also makes the output shape less predictable.
  • Default ignore list. Do lockfiles and generated output get a shipped default, or does the user opt in? A shipped default changes existing stamps.
  • Fallback shape. When even the condensed diff overflows, should the header generator run with paths only, or should the stamp skip the subagent and use deriveSubject up front instead of after three failed calls?
