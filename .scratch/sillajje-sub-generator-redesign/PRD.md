# Sillajje — Sub-generator redesign: dual parallel calls, dual-prefix taxonomy, configurable body

## Problem Statement

The current sub-generator (issue 05) has three problems:

1. **Conventional-commit prefixes don't describe interaction-only sessions.** When the agent answers a question, researches something, or explores the codebase without changing files — which is common — the subject line is forced into prefixes like `chore:` or `docs:` that misrepresent what happened. The user can't scan `jj log` and distinguish a code change from a Q&A session.

2. **A single model call produces mediocre output.** Asking `pi -p` to produce both a subject line and a summary in one output forces the model to do two distinct cognitive tasks (classify the interaction + narrate the agent's loop) in a single pass. The result is often vague summaries that fail to capture the agent's thinking process.

3. **The body structure is hardcoded.** Users can't choose which sections appear in the commit body. Someone who only wants the trace and the prompt is forced to store tool metadata and the full agent response. Someone who wants lean outputs has no way to trim the body.

4. **The sub-generator runs with tools enabled.** `pi -p` boots with full tool access, which is unnecessary for a text-generation task and opens the door to unproductive behavior (the model might try to read files rather than summarize).

## Solution

Redesign the sub-generator into **two focused, parallel headless Pi processes** (`pi -p --no-session --no-tools`) — one for the dual-prefix header, one for the trace — with a fully configurable commit body structure.

- **Header sub-generator** produces a dual-prefix subject line: `<interaction-type>/<conventional-commit>: <description>` (e.g., `debug/fix: null pointer in auth`, `answer: middleware chain explained`). The interaction type describes *what the agent did*; the conventional-commit describes *what changed*. When no files changed, the conventional-commit half is omitted.
- **Trace sub-generator** produces a compressed narrative of the agent's thinking-and-tool loop — not just the outcome, but what it thought about, what tools it called and why, what it found, and what decisions it made. Three configurable detail levels.
- **Both calls run in parallel** via `Promise.all` since their inputs are identical (transcript, diff, prior descriptions) and their outputs are independent.
- **The commit body is configurable** — every section (trace, metadata with individual field toggles, user prompt, agent response) can be enabled or disabled via `message.body.*` in the sillajje config.

## User Stories

1. As a Pi user, I want to scan `jj log` and distinguish a code-change interaction from a Q&A session at a glance, so that I can quickly find the interaction I'm looking for.
2. As a Pi user, I want the subject line to accurately classify what the agent was doing (asking, answering, debugging, planning, exploring, researching, acting), so that I don't have to click into each change to understand its purpose.
3. As a Pi user, I want the subject line to still include conventional-commit prefixes when files changed (e.g., `act/feat:`), so that I maintain compatibility with tooling that parses conventional commits.
4. As a Pi user, I want the trace to be a compressed narrative of the agent's *thinking process* — what it read, what it found, what it decided — not just the outcome, so that I can understand *why* a change was made without re-reading the full transcript.
5. As a Pi user, I want to configure the trace detail level (high-level, step-by-step, decision-focused), so that I can tune how much information is stored per interaction.
6. As a Pi user, I want the header and trace generated by separate focused model calls, so that each output is of higher quality than a single multi-purpose call.
7. As a Pi user, I want both sub-generator calls to run in parallel, so that I don't wait for two sequential model invocations.
8. As a Pi user, I want to disable the trace altogether and use the first line of my prompt as the subject (`message.header: "user_prompt"`), so that I can have minimal commit bodies when I prefer manual control.
9. As a Pi user, I want to toggle individual body sections (trace, metadata, user prompt, response) on or off, so that I control exactly what is stored in each jj change.
10. As a Pi user, I want to toggle individual metadata fields (tools, call count, elapsed, thinking blocks), so that I can strip metadata I don't care about.
11. As a Pi user, I want the sub-generator to run without tools (`--no-tools`), so that it doesn't waste resources loading tool definitions or risk the model trying to read files instead of summarizing.
12. As a Pi user, I want the sub-generator to retry on failure (up to 3 attempts), including on empty output, so that transient API errors or non-deterministic model failures don't leave gaps in my history.
13. As a Pi user, I want the header to fall back to the first line of my prompt when the sub-generator exhausts all retries, so that I never get a bare `chore: agent interaction` subject.
14. As a Pi user, I want the trace to be empty (omitted from the body) when the trace sub-generator exhausts all retries, so that I'm not shown broken or misleading content.
15. As a Pi user, I want the existing config (pre-redesign) to keep working without changes, so that I don't have to update my config file when upgrading.

## Implementation Decisions

### Dual-prefix taxonomy

A two-part prefix separated by a slash: `<interaction-type>/<conventional-commit>`.

Seven canonical interaction types, each describing the agent's mode of operation:

| Prefix | The agent was... | Example |
|---|---|---|
| `act` | Executing — files changed | `act/feat: add login form` |
| `plan` | Designing/scoping — output is a plan | `plan/chore: architecture for notifications` |
| `explore` | Reading and navigating the codebase | `explore/refactor: audit error handling` |
| `research` | Investigating external sources (docs, APIs, repos) | `research/docs: REST API pagination patterns` |
| `ask` | Asking the user a question | `ask:` |
| `answer` | Answering the user's question | `answer: middleware chain explained` |
| `debug` | Diagnosing a problem | `debug/fix: null pointer in auth` |

The conventional-commit half is omitted when no files changed. The header sub-generator picks the best interaction type and conventional-commit prefix from the full transcript — it classifies, the user doesn't have to.

### Two sub-generator calls, parallel, no tools

Both sub-generators spawn as `pi -p --no-session --no-tools -m <subGeneratorModel>`.

- `--no-session`: prevents recursive sillajje activation
- `--no-tools`: prevents the model from accessing tools — it can only generate text, which is all the task requires

Inputs for both: session transcript (user messages + extracted assistant text, sans tool outputs), the diff from `jj diff -r @-`, and up to 5 prior change descriptions from `jj log -r ancestors(sillajje/<sessionId>)`.

The calls are independent and input-identical → `Promise.all([generateHeader(...), generateTrace(...)])`.

When a sub-generator is disabled by config (header set to `"user_prompt"`, trace set to `false`), the corresponding call is skipped entirely — no process spawned.

### Prompt design — focused, single-responsibility

**Header prompt:** Asks the model to produce exactly one line — a dual-prefix subject. The model must classify the interaction type and (when applicable) the conventional-commit prefix from the transcript and diff. Example output: `debug/fix: null pointer in auth middleware`.

**Trace prompt:** Asks the model to compress the agent's thinking-and-tool loop into a narrative. Three detail levels, selected by config:

- `high` (default): 2-4 sentences of plain English — what problem was being solved, what approach was taken, what was the outcome.
- `step`: Numbered steps. Each step says what the agent did and why.
- `decision`: Focus on key insights, discoveries, and trade-offs considered — what the agent decided and why.

### Retry strategy

3 total attempts per sub-generator call. Retry on:
- Non-zero exit code (process failure, API error)
- Timeout (30 seconds, configurable via `subGenerator.timeoutMs`)
- Empty or whitespace-only output (model produced nothing — non-deterministic, worth retrying)

Fallback on exhaustion:
- Header → `deriveSubject(prompt)` — first line of user prompt, truncated to 72 characters
- Trace → empty string (section omitted from body)

### Configurable body assembly

The commit body is assembled from config-gated sections. Section order:

1. Header (the subject line — always present)
2. Trace (compressed agent-loop narrative)
3. User Prompt (raw prompt that started the interaction)
4. Metadata (tools, call count, elapsed, thinking blocks)
5. Agent Response (final text response)

Each section except the header can be individually toggled. The metadata block supports individual field toggles.

### Config schema

New keys added to `.pi/configs/sillajje.json` (backward compatible — all missing keys default to the values below):

```jsonc
{
  // (existing keys preserved)
  "debug": false,
  "workspacesRoot": "~/.pi/sillajje",
  "subGeneratorModel": "openai/gpt-4o-mini",

  // New: message structure control
  "message": {
    "header": "one_line",           // "one_line" | "user_prompt"
    "body": {
      "trace": {
        "enabled": true,
        "detail": "high"            // "high" | "step" | "decision"
      },
      "meta": {
        "enabled": true,
        "tools": true,
        "call_count": true,
        "elapsed": true,
        "thinking_blocks": true
      },
      "user_prompt": true,
      "response": true
    }
  },

  // New: sub-generator behaviour
  "subGenerator": {
    "retry": {
      "maxAttempts": 3
    },
    "timeoutMs": 30000
  }
}
```

When `message.header` is `"one_line"`, the header sub-generator is called. When `"user_prompt"`, the first line of the user's prompt is used directly — no sub-generator call.

### Output parsing

**Header:** First line of stdout, trimmed. If stdout contains multiple lines, everything after the first newline is discarded. This is the existing heuristic from issue 05 — it works reliably.

**Trace:** Entire stdout, trimmed. No parsing needed — when the model's only job is to produce the trace, its entire output is the trace.

### Module changes

The `sub-generator.ts` module is split into two export functions: `generateHeader()` and `generateTrace()`. Both accept the same `SpawnFn` adapter and `SubGeneratorContext`. The `SpawnFn` adapter and `createSpawnFn()` factory are unchanged.

The `config.ts` module's `SillajjeConfig` type expands to include `message` and `subGenerator` trees. `loadSillajjeConfig` applies defaults for all missing keys — no breaking change for existing config files.

The `metadata.ts` module's `CommitBodyData` interface replaces `summary` with `trace`, and `buildCommitBody` assembles sections based on which fields are provided (non-empty strings for text sections, non-null metadata). Callers in `index.ts` gate section inclusion based on config before calling `buildCommitBody`.

The `index.ts` `stampChange` closure is refactored: it calls `generateHeader()` and `generateTrace()` in parallel (when config enables them), with retry logic wrapping each call, and assembles the body from config-gated sections.

## Testing Decisions

### What makes a good test

Tests exercise external behavior through module interfaces. The `SpawnFn` adapter is the primary test seam — unit tests inject mocks to verify prompt construction, argument assembly, output parsing, and retry/fallback behavior without spawning real processes. Integration tests via `ExtensionRunner` verify the full `agent_end` → stamp flow with a real (or mock) sub-generator.

### Modules tested

- **Unit (vitest):** `sub-generator.ts` — expands to cover `generateHeader()` and `generateTrace()` independently. Tests: prompt template construction for each detail level, argument assembly (especially `--no-tools` flag), output parsing (header single-line, trace freeform), retry logic (3 attempts, retry on empty output), fallback behavior. Existing test patterns in `test/unit/sub-generator.test.ts` are extended.
- **Unit (vitest):** `config.ts` — new cases for partial configs with missing `message` and `subGenerator` keys (all defaults applied correctly), individual meta field toggles, backward compatibility with pre-redesign configs.
- **Unit (vitest):** `metadata.ts` — `buildCommitBody` with `trace` instead of `summary`, omit sections when fields are empty/missing. Existing test patterns in `test/unit/metadata.test.ts` are extended.
- **Integration (ExtensionRunner):** `change-stamping.test.ts` — existing tests must continue to pass (fallback to `deriveSubject` when pi is unavailable). New tests: config-gated body sections, dual-prefix subject in stamped changes, trace content in commit body.

### Prior art

Follows the existing test structure: unit tests for pure/adapter-injected modules (`test/unit/sub-generator.test.ts`, `test/unit/config.test.ts`, `test/unit/metadata.test.ts`), integration tests via `ExtensionRunner` for event handler behavior (`test/integration/change-stamping.test.ts`).

## Out of Scope

- Changing the sub-generator model per-call (header and trace always use the same `subGeneratorModel`)
- Making the interaction-type taxonomy user-extensible (the seven canonical types are hardcoded)
- Using a direct LLM API call instead of `pi -p` (kept as `pi -p --no-session --no-tools` for unified config surface)
- Exposing a way to manually override the sub-generator's chosen prefix (the user can edit `jj describe` after the fact)
- Auto-archiving or any lifecycle changes — this is purely a sub-generator and body-structure redesign
- Changing how the transcript is assembled or what constitutes the diff — those inputs are unchanged

## Further Notes

- The `SpawnFn` adapter remains the highest test seam and does not change signature.
- The sub-generator timeout was 30s, remains 30s, but is now configurable via `subGenerator.timeoutMs`.
- The existing fallback `deriveSubject` is kept as the header exhaustion fallback, not removed.
- The extension name `sillajje` is a portmanteau of the French "sillage" (wake, trail) and "jj."
- The domain glossary has been updated in `extensions/sillajje/CONTEXT.md` with the new terms (header, trace, dual prefix, interaction types).
- `buildCommitBody` in `metadata.ts` currently references `summary` — this will be renamed to `trace` throughout.
