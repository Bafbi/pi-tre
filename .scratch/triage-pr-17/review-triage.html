Finding 2 — -s @ after archive (true, fixed now)

Claim: the README says -s @ fails with no live session, but it succeeds after the current session is archived.

Verified against the tree: archive clears the workspace path and cursor but not the session key (extensions/sillajje/src/index.ts, handleArchive). resolveNewBase maps -s @ to state.getSessionKey(), which survives, and resolveBaseSource accepts an archived session's bookmark. The glossary already states the target — "An archived session is a valid Base session" — so the README was the side that was wrong. Fixed in the README, and the same sentence now distinguishes -o @ (needs a live session) from -s @.

Finding 3 — conflicted bookmark (true, decide)

Claim: resolveBaseSource() accepts a bookmark with several targets, and ensure() branches from whichever target jj.log returns first.

Verified against the tree: resolveBaseSource in packages/sillajje-workspace/src/index.ts checks the bookmark by name only and returns the name; it never reads Bookmark.target. ensure's resolveBase takes [tip], the first commit jj.log returns. Bookmark.target is typed string[] (packages/sillajje-jj/src/types.ts), so more than one target is representable. On jj 0.44.0 a concurrent bookmark move was reconciled automatically, so a multi-target local bookmark is an edge case, not the common path — but nothing in the code rejected it. The user chose (A) reject, now implemented.
