TL;DR

Two repo_query calls for the same repo ran in parallel, cloned into the same directory, and one of them deleted the other's work. The loser's failure cleanup did rm -rf <cloneTarget>, which removed the winner's in-progress clone. Both calls failed. The installed extension then discarded git's error text, so the agent saw only Failed to clone herdrdev/herdr (default branch).

The fix has three parts, and they stack:

  1. core Clone to a temp dir and publish by atomic rename. A visible clone target is then always a complete clone or absent. It is never half-written. Cleanup only ever touches the caller's own temp dir.
  2. guard Verify an existing target is real with git rev-parse -q --verify HEAD before reusing it, instead of trusting the mere presence of .git.
  3. optimize Dedupe clones per target on demand, so N parallel callers do one clone, not N, without blocking the turn and without a batch hook.

1. The incident

In one assistant turn the agent issued two repo_query calls for the same repo (two different questions). pi runs tool calls in one message in parallel by default. Both failed in under a second.

2. How cloning works today

Three concepts carry the design. The race lives in the third.

Tempspace

One temp root per session: /tmp/pi-rq-<sha256(sessionFile)[0:16]>. Created on first use, shared by every call, removed on session_shutdown.

Clone target

The directory one repo identifier resolves to: join(tempspace, dirName). For herdrdev/herdr it is github_herdrdev_herdr. It is the unit of reuse.

Parallel by default

pi executes a message's tool calls concurrently unless any of them declares executionMode: "sequential".

3. Root causes

Five things had to line up. The first two are the bug; the rest explain why it was opaque and why other sessions hit it too.

#CauseDetail
1 Shared clone target, no coordination critical Both parallel calls computed the same dirName and the same target under the shared tempspace. Two git clones wrote into one directory at once.
2 Failure cleanup deletes the shared target critical The loser ran rm -rf <cloneTarget>. That removed the winner's in-progress clone, so both failed. Cleanup of shared state is only safe when you own it.
3 Errors swallowed high The installed extension (a stale package checkout) ignored result.stderr and returned a fixed string. The working tree already captures stderr; the running copy did not.
4 No in-flight dedupe medium Duplicate calls for one repo do duplicate work. Even without the bug, N callers = N clones.
5 Presence-only reuse test medium existsSync(".git") accepts a half-written clone, and checkExistingOrigin falls through to reused when the origin cannot be read. See §4.

4. Latent bugs the race exposed

Half-written clone treated as usable

git clone creates .git early. If a process is killed mid-clone, or two race, the next call sees .git, cannot read an origin, and returns reused. The subagent then explores a broken repo, and the failure surfaces one level down.

Stuck target deadlock

A non-empty target with no valid .git (a crash, leftover junk, or a Windows empty dir) makes rename fail forever while existsSync(".git") is false. Every later call fails, and nothing repairs it.

5. Three ways to fix it

The decision is narrow: who starts a clone, and who stops two clones of one repo from colliding?

A · Dedupe on demand recommended

Each call clones what it needs. A small registry in clone.ts maps clone target → running clone, so a second caller waits for the first. Different repos still clone in parallel; explores start as soon as their clone is ready.

+ no new hook · no turn stall · clone logic stays in one file
− a little bookkeeping (map lifecycle, abort)

B · Batch pre-clone

On the assistant message's message_end, gather every repo named across all tool calls, clone each once, then let the calls consume them. This is the literal “aggregate then clone” idea.

+ faithful batch semantics
− blocks the turn before any tool row appears · still needs the per-call fallback · reads as hidden magic

C · One at a time

Declare repo_query as executionMode: "sequential". pi serializes the batch, so the second call reuses the first's clone.

+ smallest change
− serializes every tool in the batch and the subagents too

Why A. It produces the “clone each repo once” outcome you want while keeping the good property, parallel subagents, and it needs no lifecycle hook. B's seam is real but expensive. C discounts the feature the extension exists for.

The batch seam, for the record

B is genuinely possible, which is worth knowing. In pi-agent-core/dist/agent-loop.js, message_end fires with the full assistant message (all tool calls) before tool execution. Handlers receive ctx, are awaited (runner.js), and their errors are caught. There is no tool_batch event. message_end is the only pre-execution view of the whole batch.

6. The recommended fix

A · on-demand dedupe, layered on the atomic-publish clone. Staged so each stage is independently useful.

StageChangeWhy
1 Atomic publish. Clone into mkdtemp(tempspace/.tmp-<dirName>-), then rename(tmp, target). Delete mkdir(target) and every rm -rf target. The visible target becomes complete-or-absent. Cleanup only touches your own temp dir, so no caller can delete another's work.
2 Validity probe. In checkExistingOrigin, require git -C target rev-parse -q --verify HEAD to exit 0 before reuse. A half-written, unborn, or missing repo can never reach the subagent. Local no-origin clones still pass (exit 0).
3 Invalid-target recovery (R2). On rename conflict with no valid target, try rmdir(target), which succeeds only if empty, then retry once. Otherwise fail with an actionable message naming the path. Repairs the Windows empty-dir case with no data-loss window; keeps the invariant under our control instead of force-resolving externally corrupted state.
4 Dedupe map. Map<cloneTarget, Promise<CloneResult>>; entries removed when settled so failures are retryable. N parallel callers for one repo run one clone; distinct repos stay parallel. Cross-process safety is still carried by stage 1.
5 Robustness. Cleanup with rm(tmp, { recursive, force, maxRetries: 3, retryDelay: 100 }); classify signal.aborted || result.killed || result.code === null as aborted or timed-out. Windows read-only pack files; and a timeout should read as “timed out”, not a bogus git error.
6 Rename retry for Windows AV blips. Deferred: on Linux the rename outcome is deterministic. Add on a report.

New clone flow

if validTarget(cloneTarget):                 // rev-parse probe + origin match
	return checkExistingOrigin(cloneTarget)

tmp = mkdtemp(join(tempspace, `.tmp-${dirName}-`))
try {
	r = await clone into tmp                    // caller's signal, 120 s timeout
	if isAborted(r): return failed("aborted")
	if r.code !== 0:  return failed(r.stderr)   // real git text, finally
	try rename(tmp, cloneTarget)
	catch:
		if validTarget(cloneTarget): return checkExistingOrigin(cloneTarget)  // lost publish
		if rmdir(cloneTarget) ok: retry rename once                            // repair empty dir
		return failed("stale target at <path>; remove it")                     // actionable
	return cloned
} finally {
	rm(tmp, { recursive, force, maxRetries: 3 })   // our temp only, never cloneTarget
}
Platform note. fs.rename onto a missing dest or an empty dir succeeds on Linux; onto a non-empty dir it fails with ENOTEMPTY; Windows rejects even the empty case. That is exactly why the loser is detected by re-probing the target, not by reading the rename error code.

7. The invariant

A clone target is complete or absent. It is only ever created or replaced by an atomic rename. No code path deletes a target another caller may be using.

Consequences that fall out for free:

  • Reuse is safe: if .git exists, it is a real clone (then the probe confirms HEAD resolves).
  • A crash leaves only a .tmp-* dir, never a corrupt target.
  • The dirName-collision case (two repos sanitizing to one target) still returns the collision error instead of silently reusing the wrong repo.

8. Test plan (TDD)

Seams confirmed before writing anything, per the TDD discipline. No new seam is needed. The existing fake-pi unit seam and the tool seam cover it.

SeamHowWhat it proves
ensureRepoCloned(repo, tempspace, signal, pi) fake pi.exec, real temp dir the clone algorithm and the new invariants
getTempspacePath(ctx) existing workspace tests tempspace reuse per session
repo_query.execute captureExtension end-to-end parallel-call behavior

Vertical slices, smallest first

  1. Coalesce. Two concurrent calls, same target, barrier-held clone: both usable, one complete target, no cross-deletion.
  2. Collision. Concurrent calls whose clones report different origins for one dirName: loser gets the collision error, and the winner's target is still intact.
  3. Invalid target. Pre-seed .git with no HEAD: must not be reported as reused.
  4. Abort or timeout. killed:true, code:null classifies as aborted, not as a git failure.
  5. Stuck target. Non-empty target without .git: fails with an actionable message (and the rmdir path repairs the empty case).

This table is the diagnosis-time snapshot. The PRD at .scratch/repo-query-clone-race/PRD.md settles the rows below.
