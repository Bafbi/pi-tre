Wrong behavior

P1 — --pull --force ignores --force when the checkout is unchanged.

The PRD table says --pull refuses when "the Workspace hash moved since the seed" and --force the workspace. Ticket 03 repeats it: "&=nbsp;--pull refuses a path whose Workspace copy moved since the seed. Each refusal names the path."

index.ts:1462 short-circuits before the force check at :1466:

if (coHash === recorded && wsHash !== undefined) {
	report("unchanged in the checkout — nothing to pull");
	continue;
}

So when the agent edits a seeded file and the checkout has not moved, the workspace divergence is reported as "nothing to pull", and --pull --force also does nothing. There is no command path to discard a workspace edit, even though the spec promises one. The refusal test (seed.test.ts:320-341) only covers the case where both sides moved, so it passes.

Fix shape: treat the path as "nothing to pull" only when the workspace is also unchanged; otherwise refuse it by name unless force is set, then copy.
