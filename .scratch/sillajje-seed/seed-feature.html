Summary

A sillajje Workspace is a clean checkout of the Base tree. jj never materializes a gitignored file, so a session starts without .env, mise.local.toml, or .local/. Seed lets a project name those paths once, and the Workspace copies them in from the checkout that launched the session.

Opt-in

A seed list in the project config. Empty by default; nothing is copied until a project asks.

Copy, not symlink

The agent edits the Workspace copy. It never writes through to your checkout.

Never overwrites

A path already in the Workspace is skipped, so a tracked file and the agent's edits survive.

Invisible to jj

A Seed path never enters a stamp, a Fold, or jj diff.

Two-way with a check

--push and --pull move edits, refusing a path that moved on both sides.

Lifecycle-aware

Copies at creation and at Unarchive. Archive warns before it deletes.

How it works

On the first session_start that creates a Workspace, the adapter seeds it before postInit, so a post-init command can read a seeded file.

session_start→ ensure() → created→ seed paths→ write sillajje/seed→ postInit

The copy walks each listed path. A directory recurses; a path that already exists in the Workspace is skipped, so a tracked file is never overwritten. The Seed record carries the source checkout root and a SHA-256 per copied file.

Seeding runs only when ensure returns created. A reused Workspace is left alone, so a reload or resume never clobbers the agent's edits.

Unarchive rebuilds the Workspace from the session bookmark, then re-copies the config's seed list.

jj workspace add --revision bookmark→ read Seed record→ copy from record.source→ write new record

The source is the checkout the session was seeded from, not wherever the process was later launched. If that checkout is gone, Unarchive falls back to the current repo root and warns.

Archive reads the Seed record, names each seeded path whose Workspace copy differs, warns, then deletes the Workspace.

[sillajje] seed: 1 path(s) changed in the workspace and will be lost on archive:
.env

Archive never pushes. An unpushed edit to a seeded path is lost when the Workspace is deleted. Run /sillajje:seed --push first if you want it.

--push writes Workspace → checkout. --pull writes checkout → Workspace. Both compare each path's current hash on each side against the record.

--pushWorkspace → checkoutthe checkout also moved since the seedoverwrite the checkout

A missing source is reported and left alone. A missing destination is created from the surviving side. No move ever deletes a file on the other side. A successful move advances the Seed record, so the next move is measured against the synced content.

Guarantees

  • Isolation holds. The copy is a copy. The agent never writes into your checkout except through an explicit --push.
  • A tracked file is safe. Existence in the Workspace is the guard. A tracked path is already materialized, so the seed skips it.
  • Nothing is deleted. A move writes one side from the other; a path missing on the source side is reported and skipped.
  • jj never sees a Seed. Ignored paths stay out of jj status, jj diff, stamps, and folds.
  • A reload cannot clobber an edit. Seeding is gated on a newly created Workspace.
  • Archive tells you first. It names a diverged seed before deleting the Workspace.

Serve exposes seeds. /sillajje:serve serves the whole Workspace over HTTP on the LAN, so a served session hands out its seeded secrets. Serve is opt-in, so this is a choice you make per session.
