Fold — one command, appendable review branches

`fold` publishes a source delta as one clean change, records a per-source marker, and bases the next fold on it. No `--update` mode; `-o <rev>` plus `--land` covers publishing, appending, and landing.

Command

fold (-s <id|@> | -r <rev>) -o <rev>
     [--named [<branch>]] [--land] [--push] [--archive]
     [--exclude <path>] [--no-marker]

Every fold records a Folded source marker and bases its delta on the tip-most recorded tip that is an ancestor of the source. A missing marker is a normal first fold: it bases on the fork point.

FlagEffect
-o <rev>The target the folded change is placed under.
--named [<branch>]Name the folded change with a review bookmark. Empty names it fold-<change id>. It also keys the marker.
--landAdvance the target's single local bookmark to the folded change. This is how a review branch grows.
--pushPush the landed bookmark to its tracking remotes (requires --land).
--exclude <path>Leave paths out of the published change (repeatable). The source keeps them.
--no-markerIgnore the store and record none: re-aggregate from the fork point.

Model

A fold reads and writes one bookmark per source:

slj/f/<dest>/<source>   = the source tip last published to <dest>
  • <dest> — the --named branch, or the target's single local bookmark.
  • <source> — the session key, or the source bookmark (else the tip's change id) for a rev.
  • <dest> is escaped to one path segment, so review never reads markers written for review/extra.

The lookup does not read the marker's name. It takes the tip-most marker whose recorded tip is an ancestor of the source, so a handoff, a rename, or a rewrite still finds its predecessor.

Flows

Publish

fold -s @ -o main --named review

No marker yet → base fork point. The folded change is a child of main; review points at it; the marker records the session tip.

Append

fold -s @ -o review --land

The marker gives the last published tip, so only the new work is replayed. --land moves review.

Hand off

fold -s sNew -o review --land

A new session key has no marker, but the predecessor's tip is an ancestor, so the lookup finds it. Only the new work is replayed.

Concurrent sources

fold -s s2 -o review --land

Markers are per source, so s2 never reads s1's cursor and every source appends only its own work.

Land

fold -s @ -o main --land

Targets main directly. With no marker for that destination, it re-aggregates the session's net delta and advances main.

Fresh aggregate

fold -s @ -o review --land --no-marker

Ignores the store and re-publishes the whole source range from the fork point. The escape hatch.

Destination encoding

The marker's destination is escaped to one path segment, so a nested destination cannot leak into its parent's lookup.

Escapes: % → %25, / → %2F. A fold for review matches slj/f/review/, which does not match slj/f/review%2Fextra/….
