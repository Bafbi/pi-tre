1. Claimed compositions are untested — partial

Issue 01 checklist: "--rebase composes with --named, --update, --push, --archive, --exclude, and --no-marker; no new mutual exclusion." PRD user story 7 (compose with --named) and user story 10 (compose with --exclude and --no-marker) require the same. The integration suite covers --update+--rebase, --update --push --rebase, and --archive --rebase. There is no test for --named --rebase, --exclude … --rebase, or --no-marker --rebase.

These are not free paths: --named changes the marker destination, and --exclude inserts an explicit abandon between the squash and the rebase, so the interaction is worth one integration test each.

2. The cycle guard can silently not run — partial

PRD user story 15 and issue 02 require an ancestor --rebase to fail with a usage message before the sub-generator. resolveRebaseTarget guards with if (target !== undefined) (fold.ts:268) and silently skips the check otherwise. targetCommit is undefined whenever -o <rev> does not resolve to exactly one commit (fold.ts:675: targets.length === 1 ? targets[0] : undefined). A multi-commit -o revset is accepted by jj new targetRev, so an ancestor --rebase escapes the pre-generation guard and fails inside the transaction instead, spending the sub-generator call the guard exists to save.

3. PRD out of sync with shipped guards — documentation drift

The immutable guard and the merge guard are user-visible behavior that ships, and both the glossary (CONTEXT.md:23) and the ADR amendment describe them. The PRD's "Implementation Decisions", "Out of Scope", and user stories never mention either, yet the PRD status is done. Issue 04 carries them, so the requirement is recorded somewhere — but the top-level spec no longer matches the command.
